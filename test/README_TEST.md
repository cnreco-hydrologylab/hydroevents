# HydroEvents — Testing pipeline

This folder contains the testing and demonstration material for the `hydroevents` package: a unit test suite (`testing/`) that exercises the package's internals with synthetic data, and an end-to-end example (`example.py`) that runs the full workflow on sample data and produces figures/reports.

---

## Folder structure

```text
test/
├── testing/                # pytest unit test suite
│   ├── 01_test.py          # preprocessing.py
│   ├── 02_test.py          # mrc.py
│   ├── 03_test.py          # baseflow.py
│   └── 04_test.py          # events.py
├── example.py               # full workflow demo script (script version)
├── Q_example.xlsx            # synthetic hourly streamflow input
├── P_example.xlsx            # synthetic hourly rainfall input
└── output/                   # figures and report generated by example.py / TEST.ipynb
```

## `testing/` — unit tests

Run with pytest from the `test/testing` folder (or point pytest at it directly):

```bash
pytest test/testing
```

Each file targets one module of `src/hydroevents` and builds its own synthetic series in-code (no fixture files needed).

### `01_test.py` — `preprocessing.py`

Tests `preprocess_streamflow`, `fill_streamflow_gaps`, and `to_daily` on a synthetic 10-day hourly discharge series (`make_hourly_q`). Covers:

- Negative discharge values being flagged and set to NaN (`num_negative_to_nan`), and left as NaN when the run is too long to interpolate.
- Short zero-flow runs being treated as sensor dropouts and cleaned, while long zero-flow runs are kept as genuine zero flow.
- Preservation of the original series in `Q_original` when gap filling is disabled.
- Gap filling behavior: short gaps interpolated, long gaps left as NaN.
- Daily aggregation (`to_daily`) computing correct means, handling unparseable dates, and days that are entirely NaN.
- Input validation: missing `date_col`/`q_col` raise `ValueError` in `preprocess_streamflow`, `fill_streamflow_gaps`, and `to_daily`.

### `02_test.py` — `mrc.py`

Tests `compute_mrc` and its internal building blocks (recession segment extraction, inflection point detection, log-space transform, linearity filtering, segment alignment/shifting, Maillet fitting, and $k$ estimation) using synthetic exponential-recession series with known decay rate ($\alpha$).

- End-to-end: `compute_mrc` recovers a known $\alpha$ from multiple synthetic recession branches, with high $R^2$.
- `filter_segments_by_linearity` discards poorly-linear or increasing (positive slope) segments even if $R^2$ is high.
- `recession_tolerance` allows longer recession segments to be extracted from noisy/non-monotonic data.
- `identify_inflection_points` correctly finds the head→tail transition, discards runs that are too short, and validates the `skip_after_inflection` parameter.
- `transform_segments_to_log_space` computes `ln_Q`/`t` correctly and discards segments with non-positive discharge.
- `keep_longest_segment_per_decreasing_branch`, `interpolate_valid_segments`, `align_overlapping_segments`, and `apply_global_shift` are tested individually for their segment-selection/merging/shifting logic.
- `get_lh_k_from_mrc` returns correct $\alpha$/$k_{day}$/$k_{hour}$ for the `mrc`, `mean`, and `median` methods, is case-insensitive, and raises `ValueError` for missing fit results, missing negative slopes, or an invalid method name.
- `fit_maillet_model` recovers known $\alpha$/$Q_0$ from a synthetic log-linear recession and returns `(None, None)` when there isn't enough data.
- `compute_mrc` raises `ValueError` on missing columns or when no valid recession segments can be extracted from pure noise.

### `03_test.py` — `baseflow.py`

Tests `separate_baseflow`, the Lyne–Hollick digital filter (`lyne_hollick_filter`), and `compute_bfi` on a synthetic 10-day hourly streamflow series (`make_hourly_streamflow`) with a hand-built fake MRC result (`make_fake_mrc_results`).

- Physical consistency: baseflow never exceeds total discharge, baseflow and stormflow are non-negative, and BFI is in $[0,1]$.
- `k_hour` is correctly read from the MRC results for the `mrc` method, and `k_estimates` for `mrc`/`mean`/`median` are all correctly wired through `k_method`.
- Filter `direction` (`"f"`, `"r"`, `"frf"`) produces different, valid outputs.
- `nan_to_zero` correctly controls whether missing input values become 0 or remain NaN in `Q_input` (while `Q_original` always preserves the original NaNs).
- `lyne_hollick_filter` forward and reverse passes match a hand-written reference recurrence relation; a 3-pass `"frf"` filter equals sequentially chaining forward→reverse→forward single passes; filtered baseflow never exceeds streamflow.
- `compute_bfi` computes a known ratio, returns NaN for non-positive total streamflow, and behaves differently for list vs. `pd.Series` inputs with non-numeric entries (NaN propagation depends on input type).
- `separate_baseflow` supports a manual `k_hour` without MRC results, and raises `ValueError` for missing `q_col`/`date_col`, missing/invalid `k_method`/`k_estimates` entries. Also checks behavior without a `date_col` (falls back to `RangeIndex`) and that `direction` is echoed back in the results.

### `04_test.py` — `events.py`

Tests unit discharge conversion, runoff/rainfall event identification, rainfall–runoff association, event cleaning, and event-scale linear reservoir fitting.

- `discharge_to_mm` converts a known discharge value to mm correctly and raises `ValueError` for a non-positive catchment area.
- `estimate_first_peak_frac_min` falls back to a default with a single value and is clipped to `[min_frac, max_frac]`.
- `simulate_linear_reservoir`: zero runoff coefficient (`rc=0`) gives zero output; mass balance holds ($\sum Q = rc \cdot \sum P$).
- `identify_events` (runoff event/peak identification on a `Stormflow_mm` series built with `make_two_peaks_series`, a synthetic double-triangular-peak hydrograph):
  - No events detected on flat noise.
  - Two peaks separated by a deep, wide valley are split into two events (`Split_Runoff=True`).
  - Two peaks separated by a shallow valley or too close in time stay as a single, non-split event.
  - Missing required column raises `ValueError`.
- `identify_rain_events`: rain pulses far apart stay separate; close pulses are merged into one event; pulses below `min_cumulative_P` are discarded.
- `associate_events` (pairing runoff events with rainfall events, using a synthetic precipitation/runoff pair from `_make_precip_runoff_pair`):
  - A basic match succeeds with correct `PeakLag_h` and `Residual_Rain_mm`.
  - Events are discarded when the rain-to-peak lag exceeds `max_lag_h` (reason `"no_rain_within_lag"`).
  - Events are discarded when runoff efficiency is implausibly high relative to rainfall (reason includes `"efficiency"`).
  - Empty runoff-event input returns empty association/discard frames.
- `final_clean_events` filters out events with invalid runoff coefficient or that are outliers on duration/peak lag, and passes through empty input as empty frames.
- `fit_event_linear_reservoir` recovers known `rc`/`kd` parameters from a simulated linear-reservoir response and returns NaN for degenerate (all-zero) input.
- `add_linear_reservoir_fit` recovers `RC_lr`/`kd_lr_h` for a single synthetic event appended to an events dataframe.
- `test_rainfall_runoff_event_end_to_end_smoke` — smoke test for the top-level `rainfall_runoff_event` orchestrator (the only public function that wasn't otherwise covered by a direct test): drives a single synthetic rainfall pulse through a known linear-reservoir response and asserts the full pipeline wires together correctly — exactly one clean event is produced, with the expected `Event_ID`, no outliers, and rainfall/runoff volumes and `RC_lr` consistent with the known inputs.

## `example.py` — end-to-end workflow demo

Both files run the identical workflow (the notebook is a cell-by-cell copy of the script) against `Q_example.xlsx` (synthetic hourly discharge) and `P_example.xlsx` (synthetic hourly rainfall):

1. **Load & lightly smooth** the synthetic streamflow series (5-point centered rolling mean), then **inject artificial data issues** into a copy of the series: a short zero-flow run, a short gap, an intermediate gap, and a run of negative values — used later to visually check preprocessing.
2. **Preprocessing** (`preprocess_streamflow`) — cleans the corrupted series and aggregates it to daily.
3. **MRC** (`compute_mrc`) — fits the Master Recession Curve on the daily series.
4. **Baseflow separation** (`separate_baseflow`) — Lyne–Hollick filter using the MRC-derived recession constant, reports BFI.
5. **Event identification** (`rainfall_runoff_event`) — identifies runoff/rain events, associates them, filters outliers, and prints a per-event report (rain/runoff start-end, peaks, volumes, runoff coefficient).
6. **Outputs**, written to `output/`:
   - `event_report.xlsx` — table of clean events and their metrics.
   - `figure_01_preprocessing.png` — corrupted vs. preprocessed series around each artificial issue.
   - `figure_02_mrc.png` — MRC recession points with the fitted Maillet curve.
   - `figure_03_baseflow.png` — total discharge, baseflow, and direct runoff over the plotting window.
   - `figure_04_events_metrics.png` — 3-panel figure: event identification on the stormflow/rainfall series, rainfall vs. runoff volume, and rainfall vs. simulated runoff coefficient.
   - `figure_04_event_identification.html` — interactive Plotly view of stormflow/rainfall with event windows and peaks (range slider enabled).

### Inputs

- `Q_example.xlsx` — synthetic hourly streamflow (`Date`, `Q`).
- `P_example.xlsx` — synthetic hourly rainfall (`Date`, `P`).
